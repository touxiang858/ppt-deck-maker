# 用免费的 DeepSeek 网页版做 PPT · 边际成本 ≈ 0

> 「想结构」交给免费网页版 DeepSeek，「排版」交给本地引擎。
> 一份 25 页的提案，除了图片，不花一分钱。

---

## 它是什么

一个**本地小工具 + 一套提示词**，把做 PPT 拆成两半：

| 谁干 | 干什么 | 花钱吗 |
|---|---|---|
| 网页版 DeepSeek（免费） | 把内容组织成一份 JSON（说清每页讲什么、用哪种版式） | 不花钱 |
| 本机引擎（离线） | 把 JSON 渲染成 .pptx | 不花钱 |

---

## 三步

1. **扫素材**：把素材文件夹拖进工具 → 清单自动进剪贴板
2. **贴提示词**：把「身份卡 + 方案 + 图片路径」三份 MD 发给 DeepSeek → 拿回一份 JSON
3. **拖回去渲染**：JSON 拖进工具 → 出 pptx

---

## 优点

1. **边际成本 ≈ 0**。出结构用免费网页版，渲染在本机离线跑。
2. **每页只要说「讲什么」**。实测每页约 200 token；直接写 python-pptx 代码要 394 token——**少一半**，而且不用管坐标、字号、配色。
3. **产出规整、成套**。所有页面共用一套主题（色/字号/页脚/边距），不会一页一个样。
4. **素材与成品不出本机**。渲染全程不联网，只有「想结构」那步用了网页对话。
5. **AI 能改模板**（见下一节）。版式不是固定菜单。
6. **出错能定位**。JSON 结构固定，校验会直接告诉你"第几页缺哪个字段"，不像生成的代码坏了一眼看不出。
7. **一次配好，长期复用**。模板、提示词、素材清单流程固定后，第二份开始几乎只是换内容。

---

## 缺点（请逐条对照自己能不能接受）

1. **它做的是排版，不是设计**。产出的是「规整」，不是「惊艳」。**视觉冲击力全靠你的图**。
2. **图片要你自己准备**。工具只负责嵌入，不生成图。这是唯一剩下的成本和工作量。
3. **必须装 Node.js**。本地渲染依赖 Node + pptxgenjs；发布包里不带 Node。
4. **网页版有输出长度限制**。25 页一次可能被截断，截断的 JSON 直接失败。要么先出提纲、分段出，要么接受返工。
5. **免费额度有频次限制**。连着做十几份可能被限流。真要批量，还得走 API——那就又花钱了。
6. **中文字体依赖微软雅黑**。换到没装这个字体的机器，字体会回退，版式会走样。
7. **模板是「够用」，不是「精致」**。25 种版式覆盖常见场景，追求独特版式的项目会觉得千篇一律。
8. **AI 会写错内容，工具查不出来**。校验只能保证**格式**对，**不能保证事实**对。年份、数据、结论必须自己核。
9. **不做动画和交互**。出的是静态稿。
10. **以 Windows 为主**。引擎本身跨平台，但打包、字体、路径都是按 Windows 调的。
11. **改模板要懂一点点结构**。不是纯点按钮，得愿意让 agent 动代码、再试渲一页看效果。

---

## 模板不是固定的（这是它最容易低估的一点）

引擎里没有"写死的版式"，只有**一张模板表**（```deck-engine.js```）：一种页面 = 一段渲染函数 + 一行必填字段声明。

所以你能做三件事：

| 动作 | 怎么做 | 例子 |
|---|---|---|
| **改** | 调整已有版式的坐标、字号、配色、留白 | 把标题字号从 26 调到 22 |
| **加** | 让 AI agent 照现有写法加新页面类型 | 这套工具从 **7 种版式扩到 25 种**就是这么加的 |
| **减** | 删掉用不上的版式，让 AI 的选择更聚焦 | 只留 6 种，输出更稳 |

**前提**：改完要试渲一页用眼睛看。引擎有静态校验，但**版式好不好看，机器判断不了**。

这意味着一件很实际的事：**用得越久越合身**。做两三份之后，你的常用版式就固定下来了，之后每份都省。

## 谁适合 / 谁不适合

**适合**

- 有现成素材图、要交**成套**提案的人（设计/文创类学生、答辩、作品集）
- 要做方案/汇报、公司电脑不让乱装软件、也不想为 AI 付费的人
- 一个系列要批量出多版本的小工作室

**不适合**

- 要「惊艳设计」的人 —— 它给的是规整，不是创意
- 想全自动的人 —— 图要自己准备，提纲要过一次脑
- 不能装 Node.js 的人 —— 这是硬门槛
- 要在线协作、云端编辑的人 —— 它是本地工具，不是 SaaS
- 要花哨动效的人 —— 出的是静态稿

| 项目 | 结果 |
|---|---|
| 每页产出 token | **本方案 200** / 手写代码 394（省 49%） |
| 一份 25 页稿 | **本方案 5,003 token** / 手写 python-pptx 9,862 token |
| 折成钱（输出 ¥4/百万） | 本方案 ¥0.020 / 手写代码 ¥0.039 |
| API 长会话的真实账单 | 53 个会话、10,621 步 = **¥134.42 / 三周** |

> **最后一行才是重点**：把「想结构」搬到浏览器里，省下的不是写 JSON 的那点 token，
> 而是**整条 agent 会话的钱**。

## 已知边界

- 渲染依赖 `engine/deck-engine.js` 或本地 ```engine/``` 目录下的同名引擎
- 打包后的 exe 需要与 `_internal\` 和 ```engine/``` 一起保留，单独拿走 exe 跑不了
- 图片目录必须是**单层**（引擎按文件名找图）
- 参考文物照片等**来源不明的图不要放进仓库**，有版权风险
